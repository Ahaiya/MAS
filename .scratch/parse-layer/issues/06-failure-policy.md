# 06 — 失败与并发策略

**What to build:** 一次提交含 N 个文件时的编排：并发、失败、超时。

**Blocked by:** 04, 05

**Status:** done

- [x] N 个文件**并发**提交 N 个 job、统一轮询（轮询是纯等待，串行等于把等待时间乘 N）
- [x] **任一文件失败 → 整个 submission 失败**：不产出 `package.json`，命令非零退出
- [x] **不做部分成功组包**——材料缺一块，后面每个判断都建立在残缺输入上，而教师只会看到一个偏低的分数、看不出原因
- [x] 失败时成功文件的 raw **仍然落盘**（不扔掉已付费的结果）
- [x] 超时：打印 job id 后退出，提示 24 小时内可续查
- [x] 错误信息是人话，指出是哪个文件、哪类失败
- [x] 测试：一个文件失败则无 package 且非零退出、成功文件的 raw 仍在、并发下错误不被吞

## Comments

这条与引擎内部的"失败隔离"取向相反，是有意为之：引擎隔离的是同一份材料上的多个判断（缺一个仍然诚实），这里缺的是材料本身。
