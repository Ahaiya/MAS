# 需求文档 (PRD)：MAS 自动化评价可视化与人工审核系统

## 1. 产品定位与核心目标

本前端界面是一个专门面向教师/评审专家的“沉浸式智能评估审核工作台”。主要用于可视化呈现 MAS 评分之后的 artifacts/ 下的产物。

其核心目标不是完全替代教师打分，而是**将底层多智能体（MAS）的背靠背评估过程、证据链条与评价量规进行高透明度的可视化呈现**。通过极低成本的交互，辅助专家验证评分的合理性、逻辑的连贯性，并完成最终的裁决与定稿。

## 2. 核心数据结构映射 (前端视角)

前端界面的层级将严格忠于底层的 `1 : N : M` 嵌套关系：

- **Task（项目）**：全局工作区，即 对于不同的项目 会有不同的量规。
- **Student（学生）**：通过左侧边栏（Sidebar）进行无缝切换； 一个项目 会有不同的学生（样本）但是提交的内容是同质的，比如都是 与 AI 的对话记录。
- **Dim（二级评价指标，如 A4）**：右侧面板的顶级手风琴折叠卡片。 对同一个学生 有不同的评价维度，比如 A4、B1 等
- **观测点（如 A4_1）**：折叠卡片内纵向排布的子模块，包含具体的打分、理由、证据与量规。最小的打分单位， 比如在 A4 指标下 设置了 3 个观测点 A4_1等

## 3. 界面布局架构

系统采用 **“左-右”** 经典沉浸式布局，最大化利用宽屏空间：

- **左侧边栏（20% 宽度）**：学生名单与流转状态（鼠标放置时显示，平常隐藏）。
- **左栏（60% 宽度）**：学生原始文本与沉浸式阅读区。
- **右栏（40% 宽度）**：MAS 多维评估逻辑展示与定稿控制台。

------

## 4. 核心功能模块详细说明

## artifact/ 目录结构

artifact/ {项目名称即 task}/ {样本名称即学生姓名}/{二级指标即 A4、B1 等}/ 里面是实际产物，最主要的是 feedback.json

### 模块一：全局导航与状态管理（左侧边栏）

- **无缝流转名单**：展示当前 Task 下的所有学生列表（因为同一份样本会经历）。点击姓名即可静默刷新工作区域，不发生整页跳转。
- **极简状态指示**：名单附带状态标识。未处理为默认态，审核完毕且点击过“Release”定稿的学生，姓名旁呈现醒目的 ✅ 图标。

### 模块二：沉浸式证据溯源阅读区（左栏）

- **底色浅高亮标记**：初次加载时，正文中被 MAS 提取为“证据（Quote）”的句子将带有极浅的背景色（**默认是 第一个二级指标的证据，随后如在右侧切换指标 则证据高亮也随之改变）**，以提示关键信息，但不干扰正常阅读。
- **“做加法”的数据飞轮（手动增补）**：
  - **行为**：当教师划选一段未被系统识别的文本时，光标附近悬浮弹出快捷菜单（该功能仅在 文本展示区生效，即学生提交的文本 才可能会被选为证据）。
  - **功能**：允许教师手动将其标记为特定观测点的“新证据”。该操作不仅在前端生效，还需在后台记录，作为后续优化证据抽取 Agent 的先验知识（Few-shot）。
- **双向联动锚点（核心交互）**：
  - **行为**：点击正文中的任何高亮证据，右侧面板会自动对该证据对应的“打分理由”进行视觉深色高亮并产生连线。 同理 点击打分理由，也会在正文中高亮对应的证据，两者之间有线连接

### 模块三：逻辑自证与定稿控制台（右侧栏）

此模块是系统的灵魂，负责呈现打分合理性并赋予专家最高裁决权。采用纵向手风琴（Accordion）结构排布。

#### 3.1 观测点详情展示面板 (呈现逻辑连贯性)

顶部具有导航栏，横向分布已经评估的二级指标，下侧内容 由其点击展开，默认展开第一个二级指标。

在展开某个具体的指标（如 A4）后，纵向展示其下属的 3 个观测点。每个观测点卡片内必须包含以下视觉元素：

- **基准展示区**：鼠标放置悬浮显示该观测点的**打分量表（Rubric）**，让专家一眼明确“依据什么打分”。
- **评分过程展示区**：
  - 首先展示 最终输出的 feedback文本 和该观测点的分数
  - 下面是 rater1 与 rater2 的评分分数以及对应的评分理由（rationale）
  - 若有则需要展示 rater3 的 评分分数和理由

#### 3.2 逆向溯源交互

- **行为**：当教师在阅读右侧的打分理由或证据引用时，点击引用文本，正文区域将自动平滑滚动至该句子的精确位置，并施加强高亮，同时略微暗化周围文本以实现视觉聚焦。

#### 3.3 人工微调与定稿区

- **Feedback 原地编辑**：针对 MAS 生成的最终评语（拟人化总结）以及最终的分数，提供轻量级的原地文本输入框。允许专家将原文本作为草稿进行逐字重写或润色。中间过程（Agent 打分）不可编辑，以保持原始数据的真实性。
- **Release**：位于右侧面板底部。专家核对所有指标与反馈无误后点击。点击后：
  1. 更新左侧栏该学生的状态为 ✅。
  2. 触发后台保存动作，将最终确认的分数与文本写入数据库【这里需要设计接收位置，主要是两个内容 一个是证据抽取的 context； 另外一个是 scorer 的 context】。
