# MAS 前端当前功能说明

本文档用于总结当前 `frontend/` 目录下审核工作台的实际实现能力，描述当前版本已经支持的功能、数据来源方式、主要交互和现阶段约束。

## 1. 当前入口

- 页面入口：`frontend/index.html`
- 本地访问地址：`http://127.0.0.1:4174/frontend/index.html`
- 运行方式：在仓库根目录执行 `python3 -m http.server 4174`

## 2. 产品形态

当前前端是一个桌面端网页审核工作台，采用：

- 左侧收起式学生侧边栏
- 中间原文阅读区
- 右侧 MAS 审核与定稿区

当前版本明确按桌面网页设计，不提供移动端适配。

## 3. 数据读取与组织方式

前端当前会自动扫描并加载以下数据：

- `artifacts/{task}/{sample_name}/{dim}/`
- `data/training/{task}/{sample_name}.md`
- `configs/rubrics/dimension/{dim}_rubric.yaml`

具体行为如下：

- 自动发现 `artifacts/` 下真实存在且包含 `feedback.json` 的维度目录
- 自动将样本与对应的 `data/training/*.md` 原文关联
- 自动读取每个维度的 rubric anchors
- 按样本组织为：
  - Task
  - Sample
  - Dimension
  - Observation

## 4. 左侧边栏功能

左侧边栏当前支持：

- 展示当前 task 下已发现的样本列表
- 显示样本状态：`待审核` / `已 Release`
- 点击样本后静默切换当前工作区内容，不发生整页跳转
- Hover 展开更多样本信息

## 5. 左侧原文阅读区

左侧阅读区当前支持：

- 展示 `data/training/{task}/{sample_name}.md` 的完整原文内容
- 保留样本头部元信息
- 保留系统、导师、学生等各类原始对话段落
- 不再对导师内容做摘要压缩
- 按当前维度渲染对应证据高亮
- 支持在原文中人工划词，补充为某个观测点的证据

当前阅读区中的证据表现为：

- 仅高亮命中的证据片段
- 不再暗化其他正文
- 被激活的证据会有更强的高亮状态

## 6. 右侧审核区

右侧当前支持按维度展示完整审核过程：

- 顶部维度导航
- 当前维度分数
- 各观测点分数
- 是否触发裁决的状态提示

每个观测点卡片当前包含：

- 观测点名称与得分
- 量表悬浮窗
- 最终分数编辑
- 最终反馈编辑
- 证据引用列表
- 裁决记录
- `rater_1 / rater_2 / rater_3` 的评分过程展示

当前右侧支持多个观测点同时展开，不再限制只能打开一个。

## 7. 量表展示

量表内容当前来自：

- `configs/rubrics/dimension/*.yaml`

当前行为：

- 鼠标悬浮“查看量表”可显示对应 observation 的 rubric anchors
- 按 `5 分 / 4 分 / 3 分 / 2 分 / 1 分` 分块展示
- 会对 YAML 中的人工折行做整理，尽量显示为自然段，而不是原始换行

## 8. 分数计算

当前维度分数显示规则：

- 由该维度下各观测点分数做加权平均
- 当前默认所有观测点等权
- 页面显示保留两位小数

## 9. 左右联动能力

当前已经实现以下联动：

- 点击左侧原文中的高亮证据，可联动右侧对应 observation
- 点击右侧可定位证据，可跳转到左侧原文中的对应位置
- 如果右侧证据没有精确高亮目标，但能找到所属原文段落，则退回跳到对应段落

当前联动规则已经调整为：

- 右点左时，只驱动左侧定位
- 左点右时，才驱动右侧滚动到对应 observation

## 10. 不可定位证据处理

当前部分证据来自过程产物而非学生原文，例如：

- `@creative`
- `@kano`
- `@market_supervision`

这类证据在 `sample.md` 中没有原文落点，因此当前处理为：

- 右侧不再把它们渲染成可点击跳转按钮
- 明确显示为“无原文定位”

## 11. 人工编辑与定稿

当前支持以下人工操作：

- 修改 observation 最终分数
- 修改 observation 最终反馈
- 在左侧划词补充人工证据
- 清空当前样本的人工增补证据
- 点击 `Release` 将当前样本标记为已定稿

当前 `Release` 的表现主要是前端状态更新，便于审核流演示。

## 12. 当前视觉与布局特征

当前版本的视觉与布局特点包括：

- 桌面端两栏工作台布局
- 左侧原文区随整页自然延展
- 右侧审核台固定在视口中，内部独立滚动
- 左侧头部当前不固定
- 右侧顶部已经简化，只保留维度导航与分数概览

## 13. 当前已知约束

当前前端仍有以下边界或约束：

- 仅适用于桌面宽屏场景
- 依赖静态服务提供目录索引，不能直接双击本地 HTML 打开
- 样本解析依赖当前 `sample.md` 结构约定
- 右侧证据能否精确跳转，取决于 `feedback.json` 中 quote 是否能在原文中找到
- `Release`、人工补证等操作当前主要保存在前端运行态，尚未接入正式后端持久化接口

## 14. 当前代码结构

- `frontend/index.html`：静态入口
- `frontend/styles/app.css`：页面视觉与布局
- `frontend/src/main.js`：启动与数据加载
- `frontend/src/app.js`：UI 渲染与交互逻辑
- `frontend/src/state.js`：前端状态初始化
- `frontend/src/data/loadReviewData.js`：目录扫描、artifact 映射与 rubric 读取
- `frontend/src/data/parseSampleMarkdown.js`：样本原文解析

## 15. 适合下一步继续推进的方向

后续可以继续沿以下方向演进：

- 继续稳定左右联动和滚动细节
- 把 `app.js` 拆成更清晰的视图模块
- 接入正式后端保存接口
- 引入更多真实样本进行验证
- 将“不可定位证据”和“原文证据”进一步做分组展示
